基础知识/ C++

熟练度标准与自测

这份自测判断什么

这份自测用于判断一个人能否安全、独立地维护现代 C++ 工程。判断依据包括解释、编码、代码评审和排障能力，不以背诵术语为主。

能力分级

级别典型表现
入门能写基本函数和类，但容易混淆指针、引用、生命周期和所有权
可用能使用常见 STL、RAII 和智能指针完成边界清晰的小模块
熟练能独立维护中等规模模块，处理对象语义、并发、性能和工程排障
深入能解释语言与 ABI 的关键细节，设计基础库并处理复杂跨平台问题

达到“熟练”不要求每道题都答对，但应满足以下条件：

  1. 基础语义、生命周期和资源管理不能有系统性盲区。

  2. 能写出正确代码，并说明异常路径、边界条件和所有权。

  3. 能发现代码中的未定义行为、失效引用和数据竞争。

  4. 能使用工具验证判断，而不是完全依赖猜测。

  5. 对不确定的标准细节，知道需要查什么、如何设计最小实验。

六个考察维度

1. 基础语义

  • 值类别、引用、指针、const 和类型转换

  • 作用域、存储期、链接属性和未定义行为

  • 参数传递、重载、默认参数和返回值

2. 对象与资源

  • 构造、析构、虚函数和对象切片

  • Rule of Zero、Rule of Five、拷贝与移动

  • RAII、智能指针、所有权和异常安全

3. 标准库与现代 C++

  • 容器选择、复杂度、迭代器失效

  • 算法、Lambda、范围和类型推导

  • 模板、Concept 与编译期约束的基本应用

4. 并发

  • 线程、锁、条件变量和原子操作

  • 数据竞争、死锁、可见性和生命周期

  • 知道无锁编程的适用边界，不轻易自行实现

5. 工程与工具链

  • 预处理、编译、链接、ABI 和符号

  • CMake 的目标化依赖管理

  • 调试器、AddressSanitizer、UndefinedBehaviorSanitizer、ThreadSanitizer

6. 设计与排障

  • API 所有权、错误处理和跨平台边界

  • 从崩溃栈、日志和最小复现定位根因

  • 在正确性、复杂度、性能和可维护性之间做取舍

自测方式

自测分三轮进行：

  1. 概念问答：确认是否真正理解核心语义。

  2. 代码审查：找出错误、风险并提出修改方案。

  3. 小型设计与排障：验证工程能力和取舍能力。

每个问题按 0～3 分记录：

  • 0 分：不了解，或结论会造成严重错误。

  • 1 分：知道关键词，但解释不完整或无法应用。

  • 2 分：结论正确，能覆盖主要边界。

  • 3 分：结论准确，并能说明原理、风险、替代方案或验证手段。

建议将“熟练”线设为总分达到 70%，同时基础语义、对象生命周期和资源管理三个维度均不低于 60%。代码题出现严重未定义行为或所有权错误时，应优先补该主题，而不是用其他高分抵消。

第一轮：概念诊断

  1. 指针和引用分别适合表达什么语义？函数参数在什么情况下应使用 T*、T&、const T& 或按值传递？

  2. 以下函数有什么问题？为什么编译器不一定报错？

    cpp
    const std::string& make_name() {
    std::string name = "xplay";
    return name;
}

  3. 什么是 RAII？它为什么不仅仅是“用智能指针代替 new 和 delete”？

  4. std::unique_ptr 和 std::shared_ptr 分别表达什么所有权？什么情况下使用 shared_ptr 反而说明设计可能有问题？

  5. 一个类自己持有堆内存时，为什么需要考虑拷贝构造、拷贝赋值、移动构造、移动赋值和析构？怎样优先做到 Rule of Zero？

  6. std::vector 执行 push_back 后，之前保存的指针、引用和迭代器是否仍然有效？你会如何判断？

  7. virtual 析构函数解决什么问题？是不是所有类都应该有虚析构函数？

  8. std::move 实际做了什么？调用它之后，对象一定会被清空吗？

  9. 什么是未定义行为？请举三个不局限于“数组越界”的例子，并说明你会用什么工具发现它。

  10. mutex 已经保护了容器，为什么程序仍可能存在数据竞争或死锁？

  11. 头文件里定义普通非 inline 函数，为什么可能出现链接错误？这与声明、定义和 ODR 有什么关系？

  12. 如果一段 C++ 代码只在 Release 模式崩溃，你会按什么顺序排查？

熟练级实践标准

仅完成概念问答还不足以证明熟练。最终应能独立完成一个包含以下要素的小模块：

  • 使用 RAII 管理至少一种非内存资源。

  • API 明确区分所有权、借用关系和可空性。

  • 正确处理拷贝、移动或明确禁止它们。

  • 使用 STL 容器与算法，并说明容器选择。

  • 包含错误处理、单元测试和边界用例。

  • 通过编译警告以及适用的 Sanitizer 检查。

  • 能解释一次真实崩溃或性能问题的定位过程。
