客户端开发

Activity 启动与显示流程

本篇目录 4 节
  1. 从启动请求到画面显示
  2. 组件创建：进程与 Activity 初始化
  3. 窗口接入与首帧生产
  4. 输入链路与常见误区

这篇梳理一个 Activity 从 startActivity 发起，到目标 Activity 创建、窗口接入、View 绘制，再到首帧上屏的主链路。

从启动请求到画面显示

text
App 发起 startActivity
  -> Instrumentation
  -> Binder 调用 ATMS / AMS
  -> Intent 解析 / Manifest 校验 / Task 调度 / 进程调度
  -> Zygote fork 目标进程（如果进程不存在）
  -> ActivityThread.main
  -> ClientTransaction / LaunchActivityItem
  -> performLaunchActivity
  -> Activity.onCreate / setContentView
  -> handleResumeActivity
  -> WindowManager.addView
  -> ViewRootImpl.setView
  -> WMS.addWindow / relayout
  -> measure / layout / draw
  -> Surface queueBuffer
  -> SurfaceFlinger 合成
  -> 首帧上屏

这条链路可以分成两段：

  1. 启动阶段：ATMS/AMS 判断组件能不能启动、该放到哪个任务栈、是否需要创建进程，最后让目标 App 创建 Activity。

  2. 显示阶段：Activity 创建窗口和 View 树，ViewRootImpl 接入 WMS 和 Surface，最终由 SurfaceFlinger 合成上屏。

组件创建：进程与 Activity 初始化

1. App 发起端

业务调用 startActivity 后，先在发起方 App 进程内走到：

text
Activity.startActivity
  -> Activity.startActivityForResult
  -> Instrumentation.execStartActivity
  -> Binder 调用 ATMS / AMS

Instrumentation 是请求发给 system_server 前的 App 侧入口。插件化常在这里替换 Intent，把真实插件 Activity 包装成宿主 Manifest 里已声明的 Stub Activity。

2. system_server 调度端

ATMS/AMS 收到请求后，主要处理这些问题：

  • Intent 能不能解析到目标 Activity。

  • Manifest 中是否存在对应的 ActivityInfo。

  • 权限、exported、launchMode、taskAffinity 等规则是否允许启动。

  • 新 Activity 应该进入哪个 Task。

  • 目标进程是否已存在，不存在时是否需要通过 Zygote 创建。

  • 当前 Activity 是否需要 pause，新 Activity 何时 resume。

系统允许启动 Activity 的前提是：能从已安装包的 Manifest 信息中查到合法的 ActivityInfo。

3. 目标进程和 ActivityThread

如果目标进程不存在，AMS 会请求 Zygote fork 新进程。新进程启动后进入 ActivityThread.main，准备主线程 Looper、Application 和后续组件调度。

新版本 Android 通常通过 ClientTransaction / LaunchActivityItem 把启动事务发送到目标 App；旧版本主要看 LAUNCH_ACTIVITY。目标 App 收到事务后，进入 ActivityThread.performLaunchActivity。

4. performLaunchActivity

performLaunchActivity 负责真正创建 Activity 对象：

  1. 根据 ActivityInfo 找到 LoadedApk。

  2. 从 LoadedApk 拿到 ClassLoader。

  3. 通过 Instrumentation.newActivity 创建 Activity。

  4. 创建 ContextImpl，并关联 Application。

  5. 调用 Activity.attach，绑定 token、Window、Instrumentation 等运行环境。

  6. 调用 Instrumentation.callActivityOnCreate。

  7. 进入业务 Activity.onCreate。

窗口接入与首帧生产

显示阶段：页面如何接入窗口系统

onCreate 只是 Activity 生命周期开始执行，不代表页面已经显示。setContentView 只是把业务布局放进 PhoneWindow 的 DecorView，真正接入窗口系统发生在 resume 之后。

1. 对象分工

概念所在位置职责
ActivityApp / ATMS 有记录页面身份、生命周期、任务栈入口
PhoneWindowAppActivity 持有的窗口抽象
DecorViewAppView 树根节点
ViewRootImplAppView 树根控制器，负责 traversal、输入、relayout、Surface 使用
ATMS/AMSsystem_serverActivity、Task、进程、生命周期和权限调度
WMSsystem_serverWindow token、层级、焦点、布局、输入目标、SurfaceControl
SurfaceApp 进程句柄App 写 buffer 的入口
LayerSurfaceFlinger合成单位
SurfaceFlinger独立系统进程合成所有 Layer 并输出到屏幕

2. Window、Surface、Layer 的关系

text
ActivityRecord
  -> token
    -> WindowState
      -> SurfaceControl
        -> SurfaceFlinger Layer
          -> BufferQueue
            -> App Surface

WMS 通过 SurfaceControl 控制 Layer 的位置、大小、裁剪、层级和显示隐藏。App 通过 Surface 写 buffer。SurfaceFlinger 只负责拿各个 Layer 的 buffer 做合成。

从 setContentView 到首帧上屏

resume 阶段会把 DecorView 加入窗口系统：

text
ActivityThread.handleResumeActivity
  -> WindowManager.addView(decorView)
  -> WindowManagerGlobal.addView
  -> new ViewRootImpl
  -> ViewRootImpl.setView
  -> IWindowSession.addToDisplay / relayout
  -> WMS 创建 WindowState / SurfaceControl
  -> ViewRootImpl 执行 measure / layout / draw
  -> Surface queueBuffer
  -> SurfaceFlinger 合成首帧

这里有几个关键边界：

  • WindowManager.addView 是 App 侧入口。

  • ViewRootImpl 连接 App 内 View 树和 system_server 的 WMS。

  • WMS 管窗口合法性、布局、层级、焦点和输入目标。

  • Surface 只是 buffer 通道，不负责判断窗口是否合法。

  • SurfaceFlinger 管图层合成，不理解业务 View 层级。

输入链路与常见误区

输入也走窗口体系

触摸事件不是直接给 Activity，也不是直接给 Surface。InputDispatcher 会根据 WMS 提供的窗口焦点和可触摸区域找到目标 Window，再通过 InputChannel 发给 App，最后由 ViewRootImpl 分发到 DecorView、Activity 和具体 View。

text
Kernel input
  -> EventHub / InputReader
  -> InputDispatcher
  -> 目标 Window 的 InputChannel
  -> ViewRootImpl
  -> DecorView / Activity / View

常见误区

1. ActivityInfo 是启动校验核心

没有 Manifest 中的 ActivityInfo，ATMS/AMS 不会允许直接启动目标 Activity。插件化的 Stub Activity 或宿主预声明，本质是在解决系统校验问题。

2. onCreate 不等于上屏

onCreate 只是生命周期回调。首帧显示还要经过 WindowManager.addView、ViewRootImpl traversal、Surface 提交 buffer 和 SurfaceFlinger 合成。

3. Activity 不是绘制器

Activity 是生命周期和任务栈单位。真正显示链路是：

text
PhoneWindow -> DecorView -> ViewRootImpl -> Surface -> SurfaceFlinger

4. Window 不等于 Activity

一个 Activity 可以有主窗口、Dialog、PopupWindow；也有些窗口不是 Activity，比如输入法、状态栏、导航栏、Toast、悬浮窗、壁纸。

5. ClassLoader 来自 LoadedApk

ActivityThread 创建 Activity 时会从 LoadedApk 拿 ClassLoader。插件化如果只替换 Intent、不处理类加载，最终会在创建 Activity 时出现 ClassNotFoundException。

6. 新旧 Android 启动消息不同

Android P 前主要看 LAUNCH_ACTIVITY / ActivityClientRecord；P 后主要看 EXECUTE_TRANSACTION / LaunchActivityItem。做 Hook 或源码对照时要注意版本差异。
