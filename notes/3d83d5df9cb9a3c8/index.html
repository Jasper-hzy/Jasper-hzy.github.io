鸡蛋掉落：为什么下一次要少跳一层

从固定间隔的最坏情况出发，推导递减策略、覆盖状态与一维实现。

本文讨论怎样在最坏情况下，用尽量少的投掷确定最高安全楼层，并将手工策略推广为可实现的递推。

两个鸡蛋、100 层楼的最少次数是 14。 第一枚鸡蛋从 14 层开始，之后分别增加 13、12、11 层；每次没碎，下一次就少跨一层，把剩余机会留给碎蛋后的线性检查。推广到更多鸡蛋时，用“给定次数能覆盖多少层”作为状态。

下面从每隔 10 层试一次的方案出发，找出它最坏需要 19 次的原因，再推导递减间隔、次数下界与代码实现。

背景：确定最高安全楼层

设最高安全楼层为 F，F 可以取 0 到 100：在 F 层及以下扔不会碎，从 F+1 层开始会碎。F=0 表示一楼也不安全，F=100 表示整栋楼都安全。两个鸡蛋性质相同，没碎可以继续用，碎了不能再用。

目标是无论 F 取多少，都能在尽量少的尝试内确定它。

问题：固定间隔让最坏情况越来越差

如果按下面的顺序扔第一个鸡蛋：

示意
10, 20, 30, ..., 100

它在 100 层才碎时，已经用了 10 次。此时只知道 90 层安全、100 层不安全，还要用剩下的鸡蛋依次试 91 到 99 层。最坏再用 9 次，总计 19 次。

早碎和晚碎的代价并不一样：在 10 层碎掉，最多总共用 10 次；在 100 层碎掉，却可能用 19 次。固定间隔没有考虑前面已经花掉的尝试次数。

为什么不能直接改成二分

为什么第二个鸡蛋不能继续二分？

假设还需要区分 91 到 99 层，却直接从 95 层开始。若鸡蛋碎了，之后没有鸡蛋可用，无法判断最高安全楼层究竟是 90、91，还是 94。

只剩一个鸡蛋时，每次都要从最低尚未确定的楼层开始。碎掉就得到答案，没碎再向上一层。

这决定了第一个鸡蛋最多能跳多远：一旦碎掉，留下的区间必须能用剩余次数逐层查完。

方案比较：把剩余次数分配给每个区间

在两个鸡蛋、100 层的约束下，可以先比较几种搜索方式：

做法优点代价与限制
从一楼逐层检查一枚鸡蛋即可完成，过程简单最坏需要 100 次
每隔 10 层试一次，碎后逐层检查容易构造，明显少于逐层检查最坏需要 19 次，前后区间的预算不均衡
每次取剩余区间中点鸡蛋足够时可以快速缩小范围两枚鸡蛋无法保证走完所有分支，不能直接采用
随剩余次数递减间隔平衡每次碎蛋后的总成本需要先求次数预算；更多鸡蛋时还需推广状态

选择递减间隔的原因，是它能够让晚碎时更少的剩余次数，对应更小的待查区间。接下来需要证明：每一步究竟能跨多远，以及这个策略是否已经最优。

递减间隔怎样从预算中推导出来

假设希望最多用 x 次完成。

第一下从第 k 层扔。如果碎了，已经用掉 1 次，下面还有 k-1 层需要逐层检查。因此必须满足：

1 + (k - 1) <= x 也就是 k <= x

所以第一下最多试到第 x 层。

如果没碎，已经消耗一次机会，剩下 x-1 次。下一次最多向上跨 x-1 层：若这次碎了，就要用剩余的 x-2 次检查中间楼层。

继续推下去，跳跃间隔依次是：

示意
x, x-1, x-2, ..., 1

每多扔一次，剩余次数就少一次；为了在下一次碎掉时仍能查完，中间可留下的楼层也要少一层。递减间隔由这个约束直接得到。

证明 14 次的下界并构造投掷方案

预算为 x 次时，两个鸡蛋最多覆盖：

x + (x-1) + ... + 1 = x(x+1)/2 层

这个式子既给出上限，也能构造策略。每一跳都不能超过当前剩余预算，所以最多只能覆盖这些楼层；按上述间隔跳，又确实能在每一种碎蛋情况下用剩余次数完成检查。

代入 100 层：

13 × 14 / 2 = 91 不够 14 × 15 / 2 = 105 足够

因此 13 次无法保证完成，14 次可以。

第一下从 14 层开始，之后依次增加 13、12、11 层，接近楼顶时截到 100 层：

示意
14, 27, 39, 50, 60, 69, 77, 84, 90, 95, 99, 100

可以拿几种情况检查预算：

第一个鸡蛋的情况已用次数第二个鸡蛋最多还需检查总次数上限
14 层碎11～13 层，共 13 次14
27 层碎215～26 层，共 12 次14
39 层碎328～38 层，共 11 次14
100 层碎1299 层已知安全，无需再试12
到 100 层都没碎12已知 F=10012

最后两种情况少于 14 次，是因为楼只有 100 层，用不完 105 层的覆盖能力。最坏情况下仍然需要 14 次，例如 F=12 或 F=13。

实现：用覆盖楼层数统一处理多个鸡蛋

从手工策略转为覆盖状态

两个鸡蛋时，第一次碎掉以后只剩线性检查，因此能手算出递减间隔。增加到三个鸡蛋，碎掉以后还有两个鸡蛋，下半段也可以跳跃；继续手工枚举每次跳多少层，分支很快就多起来。

一种直接的状态是“k 个鸡蛋、n 层楼，最少试几次”。但这样写递推，需要枚举第一下扔在哪层，再取碎和不碎两种情况中较坏的一边。前面的预算推导给出了更方便的方向：固定可用次数，计算最多能覆盖多少层。这样只需合并碎与不碎两个子问题，不再逐层枚举第一次的位置。

定义：

cover(k, m) = k 个鸡蛋、最多 m 次尝试，可以确定临界点的最大楼层数

第一次选定一个楼层后，会有两种结果：

  • 碎了：下面的区间交给 k-1 个鸡蛋和 m-1 次机会。

  • 没碎：上面的区间交给 k 个鸡蛋和 m-1 次机会。

再加上当前试的这一层：

cover(k, m) = cover(k-1, m-1) + 1 + cover(k, m-1) cover(0, m) = 0 cover(k, 0) = 0

这里统计的是楼层数；n 层楼有 n+1 种可能的最高安全楼层，包括 F=0。不要把两种数量混在一起。

当 k=1 时，递推得到 cover(1, m)=m，对应逐层检查。当 k=2 时，每增加一次机会，多覆盖 m 层，累计起来就是前面的三角形数。

对于 3 个鸡蛋：

cover(3, 8) = 92 cover(3, 9) = 129

所以 100 层最少需要 9 次。

压缩状态并实现 C++ 递推

递推式可以先写成二维表：行表示尝试次数，列表示鸡蛋数。当前行只依赖上一行，因此可以压缩成一个数组，并逐轮增加尝试次数，直到覆盖目标楼层。

covered[k] 保存 k 个鸡蛋当前能够覆盖的楼层数。每轮开始时，它们属于上一轮；从大到小更新，可以让两个输入都仍然是旧值。

以两个鸡蛋为例：

完成的尝试轮数covered[1]covered[2]
000
111
223
336

第一轮计算 covered[2] 时，应得到 0 + 1 + 0 = 1。若从小到大，先把 covered[1] 改成 1，再计算下一项就得到 2，相当于宣称一次投掷可以区分两层楼，这已经与题意冲突。

C++17 · 最少投掷次数
#include <algorithm>
#include <stdexcept>
#include <vector>

int minimumDrops(int eggCount, int floorCount) {
    if (eggCount < 0 || floorCount < 0) {
        throw std::invalid_argument("negative input");
    }
    if (floorCount == 0) return 0;
    if (eggCount == 0) {
        throw std::invalid_argument("at least one egg is required");
    }

    eggCount = std::min(eggCount, floorCount);
    std::vector<long long> covered(eggCount + 1, 0);
    int dropCount = 0;

    while (covered[eggCount] < floorCount) {
        ++dropCount;
        for (int eggs = eggCount; eggs >= 1; --eggs) {
            covered[eggs] = std::min<long long>(
                floorCount,
                covered[eggs - 1] + 1 + covered[eggs]
            );
        }
    }
    return dropCount;
}

内层从大到小更新，是为了让 covered[eggs-1] 仍然表示上一轮的结果。若从小到大更新，同一轮的新值会被再次使用，相当于重复花了尚不存在的机会。

数组中的值达到目标楼层数后就可以截断，后续不需要知道它究竟能覆盖多少层。这里输入楼层数是 int，中间求和使用 long long，同时对覆盖值做上限截断。

设最终需要 m 次尝试，k 为限制后的鸡蛋数，时间复杂度为 O(km)，额外空间为 O(k)。这段函数只计算最少次数；如果需要实际的投掷方案，还需要根据覆盖状态选择每次测试的楼层。

实现效果：最坏 14 次与独立算法核对

先遍历两鸡蛋、100 层的所有临界点 F=0～100，模拟前面的投掷楼层及碎蛋后的逐层检查：应当都能找到答案，最多 14 次。再对小规模输入，用“枚举第一次投掷楼层”的独立递推计算最优值，与覆盖状态算法逐项比较，避免两个实现重复同一个错误。

本地验证覆盖 1～8 个鸡蛋、0～200 层，共 1,608 组输入，结果一致；上述 101 个临界点的模拟也均通过。另检查零层、没有鸡蛋但楼层非零、负数输入及大整数中间求和。它们验证的是这段次数计算和给出的两鸡蛋策略。

固定间隔的最坏情况是 19 次，递减间隔的 101 个临界点模拟最多使用 14 次；与此同时，13 次最多覆盖 91 层的下界证明排除了更小的答案。因此，开头的 14 次既有能够完成的策略，也有不能更少的证明。

关键变化是让区间大小随剩余预算一起缩小。将这个关系写成覆盖状态后，同一套推导又支持了多个鸡蛋的实现，并通过小规模独立递推的逐项核对。
