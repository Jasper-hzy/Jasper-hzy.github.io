对象生命周期与回调

回调问题的核心是：回调保存的对象是否仍然活着，以及反注册是否真的阻止了后续回调。

常见症状

  • 页面、播放器、房间、会话销毁后仍收到 native 回调。

  • 偶现崩溃在成员函数内部，但成员字段值异常。

  • 退出流程、切后台、快速进出页面时更容易复现。

典型原因

cpp
class Player {
public:
    void start() {
        engine->setCallback([this](int event) {
            onEvent(event);
        });
    }
};

[this] 只保存裸指针，不增加引用计数，也不延长对象生命周期。对象销毁后回调仍执行，就是 use-after-free。

排查方法

  • 记录对象创建、start、stop、反注册、析构和回调到达的时序。

  • 记录回调线程，确认是否跨线程访问对象状态。

  • 查清底层反注册语义：返回时是否保证不会再调用，是否仍可能存在在途回调。

  • 若回调跨业务线程投递，继续追踪投递后的任务队列生命周期。

修复原则

  • 回调所有权要明确：回调是否延长对象生命周期，还是对象销毁后跳过回调。

  • 可跳过的异步回调用 weak_ptr。

  • 必须执行的任务用 shared_ptr 延长生命周期，但要避免循环引用。

  • 析构时反注册回调，并确认底层是否保证反注册返回后不再回调。

  • C 回调的 void* context 也需要生命周期协议，不能只靠上层对象析构。
